## Що таке delta-farmer?

Delta-farmer — це CLI-бот, який відкриває узгоджені довгі та короткі позиції за безстроковими ф’ючерсами на ваших акаунтах. Замість ставки на напрямок ринку він намагається втримувати сукупну експозицію біля нуля, водночас створюючи торговий обсяг і підтримуючи відкритий інтерес для програм балів.

Кожен торговий цикл:

1. Вибирає налаштований ринок або кошик і перевіряє повний план дій.
2. Відкриває основну позицію та врівноважує її протилежними позиціями на інших акаунтах.
3. Утримує хедж протягом заданого часу, контролюючи виконання, стан позицій і ліміти ризику.
4. Закриває всі частини позиції, витримує паузу та починає наступний цикл.

Ви керуєте акаунтами, ринками, розміром позицій, плечем, таймінгами, типом ордерів і обмеженнями безпеки. Іменовані пули можуть запускати цілком різні стратегії з однієї конфігурації, а групи акаунтів можуть торгувати паралельно.

> [!WARNING]
> Дельта-нейтральність не означає відсутність ризику. Комісії, фандинг, спред, прослизання, ліквідація, збої біржі або мосту та неповний хедж можуть призвести до збитків. Починайте з малих сум і контролюйте перші запуски.

## Встановлення

Вам знадобляться [Git](https://git-scm.com/downloads) і [uv](https://docs.astral.sh/uv/getting-started/installation/). Uv встановить закріплену версію Python і залежності з lock-файлу проєкту.

Встановіть uv на macOS або Linux:

```bash
curl -LsSf https://astral.sh/uv/install.sh | sh
```

У Windows встановіть Git і uv через PowerShell:

```powershell
winget install --id Git.Git -e --source winget
powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex"
```

Клонуйте проєкт і встановіть зафіксоване середовище:

```bash
git clone https://github.com/vladkens/delta-farmer.git
cd delta-farmer
uv sync --locked
```

## Швидкий старт

У прикладах використовується Omni. Замініть `omni` на будь-який активний застосунок із таблиці вище.

Створіть конфігурацію з вбудованого шаблону:

```bash
uv run apps/omni.py config new
```

Відкрийте `configs/omni.toml` і налаштуйте стратегію щонайменше з двома акаунтами:

```toml
leverage = 10
symbols = ["BTC", "ETH"]
symbols_per_trade = 1
use_limit = true
first_as_prime = true

trade_size_usd = { min = 140, max = 160 }
trade_duration = { min = "15m", max = "20m" }
trade_cooldown = { min = "3m", max = "6m" }

[[accounts]]
name = "acc1"
privkey = "your-private-key"
# proxy = "http://user:pass@host:port"
# cex_addr = "0xYourExchangeDepositAddress"

[[accounts]]
name = "acc2"
privkey = "your-private-key"
```

Одразу зашифруйте приватні ключі:

```bash
uv run apps/omni.py config encrypt
```

Перед торгівлею перевірте конфігурацію та стан акаунтів:

```bash
uv run apps/omni.py login
uv run apps/omni.py info
uv run apps/omni.py positions
# Потрібно лише для акаунтів із проксі
uv run apps/omni.py proxy
```

Запустіть стратегію:

```bash
uv run apps/omni.py trade
```

Один раз натисніть `Ctrl+C` для коректної зупинки. Перед завершенням стратегія закриє активні позиції. Щоб скасувати відкриті ордери та закрити всі позиції без запуску торгового циклу, виконайте:

```bash
uv run apps/omni.py close
```

## Конфігурація

### Акаунти та секрети

Кожен блок `[[accounts]]` приймає такі поля:

| Поле       | Обов’язково | Опис                                                                                                                        |
| ---------- | ----------- | --------------------------------------------------------------------------------------------------------------------------- |
| `name`     | Так         | Унікальне ім’я, яке використовується в логах, таблицях, пулах і параметрах `-a`.                                             |
| `privkey`  | Так         | Приватний ключ гаманця. Після введення зашифруйте конфігурацію.                                                              |
| `proxy`    | Ні          | HTTP-проксі окремого акаунта, за потреби разом з обліковими даними.                                                          |
| `cex_addr` | Ні          | EVM-адреса поповнення з правильною контрольною сумою, яку використовує команда `move ... cex`.                              |
| `enabled`  | Ні          | Типове значення `true`; вимкнені акаунти видно у звітах, але вони не беруть участі в торгівлі та операціях із балансом.      |

`config encrypt` захищає приватні ключі, токени Telegram і підтримувані секрети окремих застосунків. Пароль запитується під час відкриття конфігурації. Для автоматичних запусків укажіть його в середовищі або у файлі `.env` в каталозі проєкту:

```dotenv
DF_CONFIG_PASSWORD=your-config-password
```

Зберігайте пароль і окрему резервну копію початкових ключів поза машиною, на якій працює бот.

### Основні налаштування стратегії

Встановлюйте `leverage` не вище найнижчого з максимальних значень, які підтримують усі налаштовані інструменти. Виберіть рівно один спосіб задання розміру:

```toml
# Фіксований загальний номінал повного циклу
trade_size_usd = { min = 140, max = 160 }

# Або частка доступного балансу; 0.5 означає 50%
# trade_size_pct = 0.5
```

`trade_duration` визначає, як довго позиції залишаються відкритими, а `trade_cooldown` — паузу після завершеного циклу. Обидва параметри приймають діапазони та вибирають нове значення для кожного циклу. Тривалість можна задавати в секундах (`30`) або рядком, наприклад `"15s"`, `"5m"`, `"1h"` чи `"1d2h30m"`.

У класичному режимі для кожного циклу вибирається один доступний інструмент зі списку:

```toml
symbols = ["BTC", "ETH", "SOL"]
symbols_per_trade = 1
```

У режимі кошика один цикл торгує від двох до чотирьох інструментів. Значення `symbols_per_trade` має дорівнювати кількості налаштованих інструментів:

```toml
symbols = ["BTC", "ETH"]
symbols_per_trade = 2
```

### Іменовані пули

Іменовані пули дають змогу зберігати в одній конфігурації біржі незалежні стратегії з різними наборами акаунтів і торговими параметрами:

```toml
[pools.majors]
accounts = ["acc1", "acc2"]
symbols = ["BTC", "ETH"]
trade_size_usd = { min = 140, max = 160 }
trade_duration = { min = "15m", max = "20m" }
trade_cooldown = { min = "3m", max = "6m" }

[pools.stocks]
accounts = ["acc3", "acc4"]
symbols = ["HOOD", "CRCL"]
trade_size_usd = { min = 100, max = 120 }
trade_duration = { min = "10m", max = "15m" }
trade_cooldown = { min = "5m", max = "8m" }
```

Кожен увімкнений акаунт має належати рівно до одного пулу, а пулу потрібні щонайменше два акаунти. Налаштування торгівлі верхнього рівня не можна змішувати з пулами; налаштування балансу застосунку, `[telegram]` і `[[accounts]]` залишаються поза ними.

Передайте назву пулу команді `trade`. Один процес запускає один вибраний пул, тому для одночасної торгівлі кількох пулів запустіть окремі процеси:

```bash
uv run apps/<app>.py trade majors
uv run apps/<app>.py trade stocks -c configs/<app>.toml
```

### Паралельні групи

У межах однієї стратегії або іменованого пулу параметр `group_size` ділить акаунти на групи, які торгують паралельно:

```toml
group_size = 2
regroup_interval = "12h"
```

У кожній групі має бути від двох до п’яти акаунтів, а кількість увімкнених акаунтів має ділитися на `group_size` без остачі. Без групування стратегія підтримує до п’яти ввімкнених акаунтів. Якщо задано `regroup_interval`, акаунти періодично сортуються за балансом і розподіляються між новими групами. У груповому режимі `first_as_prime` ігнорується.

### Ордери та якість входу

Типово використовуються ринкові ордери. За `use_limit = true` основний акаунт починає з maker-first лімітного ордера, після чого інші акаунти хеджують його:

```toml
use_limit = true
limit_wait = "90s"
limit_wait_retries = 99
limit_market_fallback = true
first_as_prime = true
```

`limit_wait_retries` додає ще одне вікно очікування, поки найкраща ціна залишається поблизу початкової лімітної ціни. Якщо ордер усе одно не виконано, `limit_market_fallback = true` дозволяє ринковий ордер; установіть `false`, щоб натомість перервати цикл.

Перед відкриттям стратегія оцінює спред і доступну глибину книги ордерів для запланованого розміру:

```toml
max_entry_spread_pct = 0.25
entry_gate_wait = "5m"
entry_gate_poll = "3s"
```

### Налаштування безпеки

```toml
trade_heartbeat = "15s"
position_roi_limit = 0.8
combined_roi_limit = 0.1
max_failures = 0
market_hours = "auto"
```

Поки цикл відкритий, стратегія перевіряє кількість позицій, відсутні частини хеджу, розбіжність розмірів, ROI кожної позиції та сукупний ROI. Після збою циклу всі акаунти очищаються перед повторною спробою. За `max_failures = 0` спроби тривають нескінченно зі зростаючою затримкою; додатне значення зупиняє роботу після вказаної кількості послідовних збоїв.

`market_hours = "auto"` перевіряє заплановане вікно входу, `"strict"` перевіряє і вікно входу, і вікно закриття, а `"off"` вимикає перевірку розкладу. Ринки без метаданих розкладу вважаються доступними цілодобово.

Ці перевірки знижують операційний ризик, але не гарантують повного хеджу й не запобігають збиткам.

### Сповіщення Telegram

Створіть бота через [BotFather](https://t.me/BotFather), отримайте ID чату призначення та додайте:

```toml
[telegram]
token = "123456:ABC-DEF"
chat_id = "123456789"
notify = ["start", "stop", "errors", "reports"]
report_interval = "1h"
```

Після додавання токена знову виконайте `config encrypt`.

## Поповнення та інструменти гаманця

Команди `deposit` і `withdraw` керують біржовими балансами на Omni та Lighter. Команда `move` доступна в усіх EVM-застосунках і працює з балансами гаманців, маршрутами між мережами та переказами на CEX-адреси окремих акаунтів. Кожна операція показує повний план і запитує підтвердження перед надсиланням.

### Команда `move`

Запустіть `move` без аргументів, щоб перевірити ввімкнені гаманці на наявність стейблкоїнів і нативного газу в усіх підтримуваних мережах:

```bash
uv run apps/lighter.py move
uv run apps/lighter.py move -a acc1
```

Джерело та призначення задаються як `network:asset`, наприклад `arb:usdc` або `base:usdc`. Типово для кожного вибраного акаунта використовується максимально доступний баланс; `-q` задає фіксовану кількість на акаунт, а `-a` вибирає один акаунт.

Перемістіть увесь баланс токена між мережами:

```bash
uv run apps/lighter.py move arb:usdc base:usdc
```

Укажіть лише вихідну мережу, щоб зібрати всі знайдені в ній підтримувані стейблкоїни в один цільовий актив. Фіксовану кількість не можна використовувати з джерелом без зазначення активу:

```bash
uv run apps/lighter.py move bsc arb:usdc
```

Перемістіть фіксовану суму для одного акаунта:

```bash
uv run apps/lighter.py move arb:usdc base:usdc -a acc1 -q 100
```

Укажіть `cex` як призначення, щоб переказати актив безпосередньо на налаштовану `cex_addr` кожного акаунта у вихідній мережі:

```bash
uv run apps/lighter.py move arb:usdc cex -a acc1 -q 100
```

Перед використанням `cex` переконайтеся, що біржа приймає саме цей актив саме в цій мережі. Коректна адреса сама по собі не підтверджує підтримку такого поповнення.

| Код    | Мережа          | Активи           |
| ------ | --------------- | ---------------- |
| `eth`  | Ethereum        | USDC, USDT, ETH  |
| `op`   | Optimism        | USDC, USDT, ETH  |
| `bsc`  | BNB Smart Chain | USDC, USDT, BNB  |
| `base` | Base            | USDC, USDT, ETH  |
| `arb`  | Arbitrum        | USDC, USDT, ETH  |
| `rh`   | Robinhood Chain | USDG, ETH        |
| `hevm` | HyperEVM        | USDC, USDT, HYPE |

Для переміщень між мережами й активами використовується Relay. Маршрути довші за 10 хвилин або з найгіршою оцінкою втрат вище за більше зі значень $0.25 і 2% відхиляються. Залишайте достатньо нативного газу у вихідному гаманці; за потреби й наявності такої можливості маршрут також поповнить газ у цільовій мережі.

### Поповнення та виведення

Наразі автоматичні поповнення та виведення підтримують лише клієнти Omni й Lighter.

#### Поповнення

Автоматичний план поповнення доводить біржові баланси до налаштованого цільового значення. Додайте ці налаштування рівня застосунку перед будь-якими таблицями `[pools.*]`:

```toml
balance_target = 500
balance_target_jitter_pct = 2
deposit_min_amount = 10
balance_transfer_delay = { min = "2m", max = "4m" }
```

Ціль незалежно рандомізується для кожного акаунта в межах `±balance_target_jitter_pct`; установіть `0` для точного значення. Перед підтвердженням план показує надані біржею мережу й токен, поточні баланси біржі та гаманця, цільове й мінімальне значення, а також суму.

```bash
# Усі ввімкнені акаунти
uv run apps/omni.py deposit
uv run apps/lighter.py deposit

# Один увімкнений акаунт
uv run apps/omni.py deposit -a acc1
```

Перше поповнення Lighter реєструє акаунт. Після зарахування виконайте `uv run apps/lighter.py login`.

#### Виведення

Без `--full` команда зменшує біржовий баланс до `balance_target`. З `--full` вона виводить увесь безпечно доступний баланс і не потребує цільового значення:

```bash
uv run apps/lighter.py withdraw
uv run apps/lighter.py withdraw -a acc1 --full
uv run apps/omni.py withdraw -a acc1
uv run apps/omni.py withdraw --full
```

План враховує доступний за даними біржі баланс і комісії. Акаунти з відкритими позиціями або ордерами визначаються до виконання; повне виведення зупиняється, якщо хоча б один вибраний акаунт заблокований.

## Команди окремих бірж

### Реферальні коди Lighter

Застосуйте реферальний код до всіх увімкнених акаунтів Lighter або виберіть один увімкнений акаунт через `-a`:

```bash
uv run apps/lighter.py useref CODE
uv run apps/lighter.py useref CODE -a ACCOUNT
```

### Змагання Omni

Перевірте активне змагання Omni, відповідність акаунтів умовам, обсяг і місця в рейтингу. Якщо придатні акаунти ще не зареєстровані, команда запитає підтвердження перед реєстрацією:

```bash
uv run apps/omni.py competition
```

Типово Omni обробляє перевірки Cloudflare через спільний розв’язувач. Щоб використовувати особистий акаунт [Astrum](https://solver.astrum.foundation/), додайте `captcha_key = "your-key"` до конфігурації Omni й зашифруйте її або задайте `CAPTCHA_KEY` у середовищі.

## Звіти та логи

Статистика бірж кешується локально, щоб не завантажувати повну історію під час кожного запуску:

```bash
uv run apps/omni.py stats
uv run apps/omni.py stats this
uv run apps/omni.py stats W05
uv run apps/omni.py stats -g day --force
```

Зберіть спільний звіт із кешованих даних бірж за допомогою `scripts/weekly.py`:

```bash
uv run scripts/weekly.py
uv run scripts/weekly.py 0
uv run scripts/weekly.py 2026-W14
uv run scripts/weekly.py --from W14 --to W22
uv run scripts/weekly.py --burn
```

Виконайте `uv run scripts/weekly.py --help`, щоб побачити всі фільтри. Якщо звіт має містити найсвіжішу історію, спочатку оновіть потрібний застосунок командою `stats --force`.

Типово логи виводяться в термінал. Установіть `DF_LOG_FILE=1`, щоб додатково записувати торгові логи до каталогу `logs/`:

```bash
DF_LOG_FILE=1 uv run apps/omni.py trade
```

## Кілька конфігурацій

Використовуйте `-c` для вибору іншої конфігурації. Прапорець працює як до, так і після підкоманди:

```bash
uv run apps/omni.py -c configs/omni-set1.toml trade
uv run apps/omni.py trade -c configs/omni-set2.toml
```

Окремі конфігурації можна запускати в різних терміналах або сервісах. Не додавайте той самий акаунт до одночасно запущених торгових процесів.

Застосунок локально зберігає хешовані ідентифікатори гаманців для підрахунку акаунтів за рухомі 30 днів і показує коротке нагадування, якщо відповідний ключ Supporter не активний.

```bash

```

Команда показує поточний статус і пропонує активувати ключ, якщо його не налаштовано. Перевірки Supporter працюють за принципом fail-open: недоступність сервісу ніколи не блокує торгівлю, закриття позицій, поповнення, виведення або інші наявні команди. ## Змінні середовища

| Змінна                    | Призначення                                                                                                  |
| ------------------------- | ------------------------------------------------------------------------------------------------------------ |
| `DF_CONFIG_PASSWORD`      | Передати пароль шифрування конфігурації для автоматичних запусків.                                           |
| `DF_LOG_FILE=1`           | Записувати торгові логи до файлу з часовою позначкою в каталозі `logs/`.                                     |
| `DF_NO_UPDATE_NOTIFIER=1` | Вимкнути перевірку нових версій.                                                                             |
| `DF_TELEMETRY=0`          | Вимкнути анонімну операційну телеметрію.                                                                     |
| `DF_ACCOUNTS_CONCURRENCY` | Обмежити кількість одночасних запитів акаунтів; типове значення `3`.                                         |
| `DF_NO_BANNER=1`          | Приховати банер, якщо активна підписка Supporter покриває кількість локальних акаунтів.                       |
| `CAPTCHA_KEY`             | Використовувати особистий ключ розв’язувача Astrum для Omni.                                                 |
| `LOGURU_LEVEL`            | Задати рівень логування, наприклад `INFO` або `DEBUG`.                                                       |
