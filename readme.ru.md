## Что такое delta-farmer?

Delta-farmer — это CLI-бот, который открывает согласованные длинные и короткие позиции по бессрочным фьючерсам на ваших аккаунтах. Вместо ставки на направление рынка он стремится удерживать суммарную экспозицию около нуля, одновременно создавая торговый объём и поддерживая открытый интерес для программ баллов.

Каждый торговый цикл:

1. Выбирает настроенный рынок или корзину и проверяет полный план действий.
2. Открывает основную позицию и уравновешивает её противоположными позициями на остальных аккаунтах.
3. Удерживает хедж заданное время, контролируя исполнение, состояние позиций и лимиты риска.
4. Закрывает все части позиции, выдерживает паузу и начинает следующий цикл.

Вы управляете аккаунтами, рынками, размером позиций, плечом, таймингами, типом ордеров и ограничениями безопасности. Именованные пулы могут запускать совершенно разные стратегии из одной конфигурации, а группы аккаунтов могут торговать параллельно.

> [!WARNING]
> Дельта-нейтральность не означает отсутствие риска. Комиссии, фандинг, спред, проскальзывание, ликвидация, сбои биржи или моста и неполный хедж могут привести к убыткам. Начинайте с небольших сумм и контролируйте первые запуски.

## Установка

Вам понадобятся [Git](https://git-scm.com/downloads) и [uv](https://docs.astral.sh/uv/getting-started/installation/). Uv установит закреплённую версию Python и зависимости из lock-файла проекта.

Установите uv на macOS или Linux:

```bash
curl -LsSf https://astral.sh/uv/install.sh | sh
```

В Windows установите Git и uv из PowerShell:

```powershell
winget install --id Git.Git -e --source winget
powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex"
```

Клонируйте проект и установите зафиксированное окружение:

```bash
git clone https://github.com/vladkens/delta-farmer.git
cd delta-farmer
uv sync --locked
```

## Быстрый старт

В примерах используется Omni. Замените `omni` на любое активное приложение из таблицы выше.

Создайте конфигурацию из встроенного шаблона:

```bash
uv run apps/omni.py config new
```

Откройте `configs/omni.toml` и настройте стратегию как минимум с двумя аккаунтами:

```toml
leverage = 10
symbols = ["BTC", "ETH"]
symbols_per_trade = 1
use_limit = true
first_as_prime = true

trade_size_usd = { min = 140, max = 160 }
trade_duration = { min = "15m", max = "20m" }
trade_cooldown = { min = "3m", max = "6m" }

[[accounts]]
name = "acc1"
privkey = "your-private-key"
# proxy = "http://user:pass@host:port"
# cex_addr = "0xYourExchangeDepositAddress"

[[accounts]]
name = "acc2"
privkey = "your-private-key"
```

Сразу зашифруйте приватные ключи:

```bash
uv run apps/omni.py config encrypt
```

Перед торговлей проверьте конфигурацию и состояние аккаунтов:

```bash
uv run apps/omni.py login
uv run apps/omni.py info
uv run apps/omni.py positions
# Нужно только для аккаунтов с прокси
uv run apps/omni.py proxy
```

Запустите стратегию:

```bash
uv run apps/omni.py trade
```

Один раз нажмите `Ctrl+C` для корректной остановки. Перед завершением стратегия закроет активные позиции. Чтобы отменить открытые ордера и закрыть все позиции без запуска торгового цикла, выполните:

```bash
uv run apps/omni.py close
```

## Конфигурация

### Аккаунты и секреты

Каждый блок `[[accounts]]` принимает следующие поля:

| Поле       | Обязательно | Описание                                                                                                                    |
| ---------- | ----------- | --------------------------------------------------------------------------------------------------------------------------- |
| `name`     | Да          | Уникальное имя, которое используется в логах, таблицах, пулах и параметрах `-a`.                                             |
| `privkey`  | Да          | Приватный ключ кошелька. После ввода зашифруйте конфигурацию.                                                                |
| `proxy`    | Нет         | HTTP-прокси конкретного аккаунта, при необходимости вместе с учётными данными.                                               |
| `cex_addr` | Нет         | EVM-адрес пополнения с корректной контрольной суммой, который используется командой `move ... cex`.                         |
| `enabled`  | Нет         | По умолчанию `true`; отключённые аккаунты видны в отчётах, но не участвуют в торговле и операциях с балансом.                |

`config encrypt` защищает приватные ключи, токены Telegram и поддерживаемые секреты конкретных приложений. Пароль запрашивается при открытии конфигурации. Для автоматических запусков укажите его в окружении или в файле `.env` в каталоге проекта:

```dotenv
DF_CONFIG_PASSWORD=your-config-password
```

Храните пароль и отдельную резервную копию исходных ключей вне машины, на которой запущен бот.

### Основные настройки стратегии

Устанавливайте `leverage` не выше минимального из максимальных значений, поддерживаемых всеми настроенными инструментами. Выберите ровно один способ задания размера:

```toml
# Фиксированный общий номинал полного цикла
trade_size_usd = { min = 140, max = 160 }

# Либо доля доступного баланса; 0.5 означает 50%
# trade_size_pct = 0.5
```

`trade_duration` определяет, сколько времени позиции остаются открытыми, а `trade_cooldown` — паузу после завершённого цикла. Оба параметра принимают диапазоны и выбирают новое значение для каждого цикла. Длительность можно задавать в секундах (`30`) или строкой, например `"15s"`, `"5m"`, `"1h"` или `"1d2h30m"`.

В классическом режиме для каждого цикла выбирается один доступный инструмент из списка:

```toml
symbols = ["BTC", "ETH", "SOL"]
symbols_per_trade = 1
```

В режиме корзины один цикл торгует от двух до четырёх инструментов. Значение `symbols_per_trade` должно совпадать с количеством настроенных инструментов:

```toml
symbols = ["BTC", "ETH"]
symbols_per_trade = 2
```

### Именованные пулы

Именованные пулы позволяют хранить в одной конфигурации биржи независимые стратегии с разными наборами аккаунтов и торговыми параметрами:

```toml
[pools.majors]
accounts = ["acc1", "acc2"]
symbols = ["BTC", "ETH"]
trade_size_usd = { min = 140, max = 160 }
trade_duration = { min = "15m", max = "20m" }
trade_cooldown = { min = "3m", max = "6m" }

[pools.stocks]
accounts = ["acc3", "acc4"]
symbols = ["HOOD", "CRCL"]
trade_size_usd = { min = 100, max = 120 }
trade_duration = { min = "10m", max = "15m" }
trade_cooldown = { min = "5m", max = "8m" }
```

Каждый включённый аккаунт должен входить ровно в один пул, а пулу нужны как минимум два аккаунта. Настройки торговли верхнего уровня нельзя смешивать с пулами; настройки баланса приложения, `[telegram]` и `[[accounts]]` остаются вне них.

Передайте имя пула команде `trade`. Один процесс запускает один выбранный пул, поэтому для одновременной торговли нескольких пулов запустите отдельные процессы:

```bash
uv run apps/<app>.py trade majors
uv run apps/<app>.py trade stocks -c configs/<app>.toml
```

### Параллельные группы

Внутри одной стратегии или именованного пула параметр `group_size` делит аккаунты на группы, которые торгуют параллельно:

```toml
group_size = 2
regroup_interval = "12h"
```

В каждой группе должно быть от двух до пяти аккаунтов, а количество включённых аккаунтов должно делиться на `group_size` без остатка. Без группировки стратегия поддерживает до пяти включённых аккаунтов. Если задан `regroup_interval`, аккаунты периодически сортируются по балансу и распределяются по новым группам. В групповом режиме `first_as_prime` игнорируется.

### Ордера и качество входа

По умолчанию используются рыночные ордера. При `use_limit = true` основной аккаунт начинает с maker-first лимитного ордера, после чего остальные аккаунты хеджируют его:

```toml
use_limit = true
limit_wait = "90s"
limit_wait_retries = 99
limit_market_fallback = true
first_as_prime = true
```

`limit_wait_retries` добавляет ещё одно окно ожидания, пока лучшая цена остаётся рядом с исходной лимитной ценой. Если ордер всё равно не исполнен, `limit_market_fallback = true` разрешает рыночный ордер; установите `false`, чтобы вместо этого прервать цикл.

Перед открытием стратегия оценивает спред и доступную глубину стакана для запланированного размера:

```toml
max_entry_spread_pct = 0.25
entry_gate_wait = "5m"
entry_gate_poll = "3s"
```

### Настройки безопасности

```toml
trade_heartbeat = "15s"
position_roi_limit = 0.8
combined_roi_limit = 0.1
max_failures = 0
market_hours = "auto"
```

Пока цикл открыт, стратегия проверяет количество позиций, отсутствующие части хеджа, расхождение размеров, ROI каждой позиции и общий ROI. После сбоя цикла все аккаунты очищаются перед повторной попыткой. При `max_failures = 0` попытки продолжаются бесконечно с увеличивающейся задержкой; положительное значение останавливает работу после указанного количества последовательных сбоев.

`market_hours = "auto"` проверяет запланированное окно входа, `"strict"` проверяет и окно входа, и окно закрытия, а `"off"` отключает проверку расписания. Рынки без метаданных расписания считаются доступными круглосуточно.

Эти проверки снижают операционный риск, но не гарантируют полный хедж и не предотвращают убытки.

## Пополнения и инструменты кошелька

Команды `deposit` и `withdraw` управляют биржевыми балансами на Omni и Lighter. Команда `move` доступна во всех EVM-приложениях и работает с балансами кошельков, маршрутами между сетями и переводами на CEX-адреса отдельных аккаунтов. Каждая операция показывает полный план и запрашивает подтверждение перед отправкой.

### Команда `move`

Запустите `move` без аргументов, чтобы проверить включённые кошельки на наличие стейблкоинов и нативного газа во всех поддерживаемых сетях:

```bash
uv run apps/lighter.py move
uv run apps/lighter.py move -a acc1
```

Источник и назначение задаются как `network:asset`, например `arb:usdc` или `base:usdc`. По умолчанию для каждого выбранного аккаунта используется максимально доступный баланс; `-q` задаёт фиксированное количество на аккаунт, а `-a` выбирает один аккаунт.

Переместите весь баланс токена между сетями:

```bash
uv run apps/lighter.py move arb:usdc base:usdc
```

Укажите только исходную сеть, чтобы собрать все найденные в ней поддерживаемые стейблкоины в один целевой актив. Фиксированное количество нельзя использовать с источником без указания актива:

```bash
uv run apps/lighter.py move bsc arb:usdc
```

Переместите фиксированную сумму для одного аккаунта:

```bash
uv run apps/lighter.py move arb:usdc base:usdc -a acc1 -q 100
```

Укажите `cex` как назначение, чтобы перевести актив напрямую на настроенный `cex_addr` каждого аккаунта в исходной сети:

```bash
uv run apps/lighter.py move arb:usdc cex -a acc1 -q 100
```

Перед использованием `cex` убедитесь, что биржа принимает именно этот актив именно в этой сети. Корректный адрес сам по себе не подтверждает поддержку такого пополнения.

| Код    | Сеть            | Активы           |
| ------ | --------------- | ---------------- |
| `eth`  | Ethereum        | USDC, USDT, ETH  |
| `op`   | Optimism        | USDC, USDT, ETH  |
| `bsc`  | BNB Smart Chain | USDC, USDT, BNB  |
| `base` | Base            | USDC, USDT, ETH  |
| `arb`  | Arbitrum        | USDC, USDT, ETH  |
| `rh`   | Robinhood Chain | USDG, ETH        |
| `hevm` | HyperEVM        | USDC, USDT, HYPE |

Для перемещений между сетями и активами используется Relay. Маршруты длительнее 10 минут или с наихудшей оценкой потерь выше максимума из $0.25 и 2% отклоняются. Оставляйте достаточно нативного газа в исходном кошельке; при необходимости и наличии такой возможности маршрут также пополнит газ в целевой сети.

### Пополнения и выводы

Сейчас автоматические пополнения и выводы поддерживают только клиенты Omni и Lighter.

#### Пополнения

Автоматический план пополнения доводит биржевые балансы до настроенного целевого значения. Добавьте эти настройки уровня приложения перед любыми таблицами `[pools.*]`:

```toml
balance_target = 500
balance_target_jitter_pct = 2
deposit_min_amount = 10
balance_transfer_delay = { min = "2m", max = "4m" }
```

Цель независимо рандомизируется для каждого аккаунта в пределах `±balance_target_jitter_pct`; установите `0` для точного значения. Перед подтверждением план показывает предоставленные биржей сеть и токен, текущие балансы биржи и кошелька, целевое и минимальное значения, а также сумму.

```bash
# Все включённые аккаунты
uv run apps/omni.py deposit
uv run apps/lighter.py deposit

# Один включённый аккаунт
uv run apps/omni.py deposit -a acc1
```

Первое пополнение Lighter регистрирует аккаунт. После зачисления выполните `uv run apps/lighter.py login`.

#### Выводы

Без `--full` команда уменьшает биржевой баланс до `balance_target`. С `--full` она выводит весь безопасно доступный баланс и не требует целевого значения:

```bash
uv run apps/lighter.py withdraw
uv run apps/lighter.py withdraw -a acc1 --full
uv run apps/omni.py withdraw -a acc1
uv run apps/omni.py withdraw --full
```

План учитывает доступный по данным биржи баланс и комиссии. Аккаунты с открытыми позициями или ордерами определяются до выполнения; полный вывод останавливается, если хотя бы один выбранный аккаунт заблокирован.

## Команды отдельных бирж

### Реферальные коды Lighter

Примените реферальный код ко всем включённым аккаунтам Lighter либо выберите один включённый аккаунт через `-a`:

```bash
uv run apps/lighter.py useref CODE
uv run apps/lighter.py useref CODE -a ACCOUNT
```

### Соревнование Omni

Проверьте активное соревнование Omni, соответствие аккаунтов условиям, объём и позиции в рейтинге. Если подходящие аккаунты ещё не зарегистрированы, команда запросит подтверждение перед регистрацией:

```bash
uv run apps/omni.py competition
```

По умолчанию Omni обрабатывает проверки Cloudflare через общий решатель. Чтобы использовать личный аккаунт [Astrum](https://solver.astrum.foundation/), добавьте `captcha_key = "your-key"` в конфигурацию Omni и зашифруйте её либо задайте `CAPTCHA_KEY` в окружении.

## Отчёты и логи

Статистика бирж кешируется локально, чтобы не загружать полную историю при каждом запуске:

```bash
uv run apps/omni.py stats
uv run apps/omni.py stats this
uv run apps/omni.py stats W05
uv run apps/omni.py stats -g day --force
```

Соберите общий отчёт из кешированных данных бирж с помощью `scripts/weekly.py`:

```bash
uv run scripts/weekly.py
uv run scripts/weekly.py 0
uv run scripts/weekly.py 2026-W14
uv run scripts/weekly.py --from W14 --to W22
uv run scripts/weekly.py --burn
```

Выполните `uv run scripts/weekly.py --help`, чтобы увидеть все фильтры. Если отчёт должен включать самую свежую историю, сначала обновите нужное приложение командой `stats --force`.

По умолчанию логи выводятся в терминал. Установите `DF_LOG_FILE=1`, чтобы дополнительно записывать торговые логи в каталог `logs/`:

```bash
DF_LOG_FILE=1 uv run apps/omni.py trade
```

## Несколько конфигураций

Используйте `-c` для выбора другой конфигурации. Флаг работает как до, так и после подкоманды:

```bash
uv run apps/omni.py -c configs/omni-set1.toml trade
uv run apps/omni.py trade -c configs/omni-set2.toml
```

Отдельные конфигурации можно запускать в разных терминалах или сервисах. Не добавляйте один и тот же аккаунт в одновременно работающие торговые процессы.

## Конфиденциальность и подписка Supporter

Delta-farmer отправляет анонимную операционную телеметрию: хешированный идентификатор машины, названия приложения и команды, сведения о платформе и версии, а также общие флаги функций. В неё не входят приватные ключи, адреса кошельков, балансы, названия инструментов и размеры сделок. Установите `DF_TELEMETRY=0`, чтобы отключить телеметрию.

Вы можете [купить подписку Supporter или сделать пожертвование через @deltafarm_bot](https://t.me/deltafarm_bot). Подписка помогает оплачивать поддержку проекта, при этом все функции под лицензией MIT остаются доступны без оплаты. Приложение локально хранит хешированные идентификаторы кошельков для подсчёта аккаунтов за скользящие 30 дней и показывает короткое напоминание, если подходящий ключ Supporter не активен.

```bash
uv run apps/omni.py license
```

Команда показывает текущий статус и предлагает активировать ключ, если он не настроен. Проверки Supporter работают по принципу fail-open: недоступность сервиса никогда не блокирует торговлю, закрытие позиций, пополнения, выводы и другие существующие команды. При активной подписке, покрывающей количество локальных аккаунтов, можно установить `DF_NO_BANNER=1`, чтобы скрыть баннер при запуске.
